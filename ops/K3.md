## 什么是 spine triton

Spine triton 是面向 RISC\-V 处理器的 AI 算子编程与编译框架。基于开源 triton 生态，使开发者能够使用类似 GPU triton 的编程方式，在RISC\-V CPU 及其 AI 计算核心上开发高性能 AI 算子。

Spine triton 的目标是让 RISC\-V 处理器也能方便的运行经过硬件优化的 triton AI 算子。

## 向量加法算子实现

vec\_add：将两个一维向量逐元素相加，并将结果保存到输出向量

数学表达式：$out[i] = x[i] + y[i]$

程序：

```Python
# vec_add.py — 第一个 spine-triton kernel（block pointer 风格）
import torch
import triton
import triton.language as tl
from triton.backends.spine_triton.driver import CPUDriver

# spine-triton 是 CPU 后端。Triton 默认假设自己运行在 GPU 上，
# 所以必须显式激活 CPU driver（每个程序入口做一次即可）。
triton.runtime.driver.set_active(CPUDriver())


# ───────────────────────── kernel（在“设备”上执行）────────────────────────
@triton.jit
def add_kernel(
    x_ptr,                       # 输入向量 x 的首地址（指针）
    y_ptr,                       # 输入向量 y 的首地址
    out_ptr,                     # 输出向量的首地址
    n_elements,                  # 向量长度（普通运行期参数）
    BLOCK_SIZE: tl.constexpr,    # 每个 program 处理多少个元素（编译期常量）
):
    # 我是几号 program？（grid 是一维的，所以 axis=0）
    pid = tl.program_id(axis=0)

    # block pointer：把“整块数据长什么样”描述给编译器
    #   base       —— 从哪个地址开始
    #   shape      —— 整个缓冲区一共有 98432 个元素
    #   strides    —— 每下标走 1 个元素（连续向量）
    #   offsets    —— 我这个 program 从哪里读：pid * BLOCK_SIZE
    #   block_shape—— 我一次拿 BLOCK_SIZE 个元素
    #   order      —— 内存布局中哪一维最连续（一维时就是 (0,)）
    x_block_ptr = tl.make_block_ptr(
        base=x_ptr,
        shape=(n_elements,),
        strides=(1,),
        offsets=(pid * BLOCK_SIZE,),
        block_shape=(BLOCK_SIZE,),
        order=(0,),
    )
    y_block_ptr = tl.make_block_ptr(
        base=y_ptr,
        shape=(n_elements,),
        strides=(1,),
        offsets=(pid * BLOCK_SIZE,),
        block_shape=(BLOCK_SIZE,),
        order=(0,),
    )
    out_block_ptr = tl.make_block_ptr(
        base=out_ptr,
        shape=(n_elements,),
        strides=(1,),
        offsets=(pid * BLOCK_SIZE,),
        block_shape=(BLOCK_SIZE,),
        order=(0,),
    )

    # 按块加载。boundary_check=(0,)：越界检查第 0 维（唯一的一维）。
    # 最后一个 program 分到的块可能超出 n_elements，越界部分自动按
    # padding 处理，不访问内存——不需要手写任何下标比较。
    x = tl.load(x_block_ptr, boundary_check=(0,))
    y = tl.load(y_block_ptr, boundary_check=(0,))

    output = x + y

    # 按块写回（越界位置不写）
    tl.store(out_block_ptr, output, boundary_check=(0,))


# ───────────────────────── host（在你的 Python 里执行）─────────────────────
def add(x: torch.Tensor, y: torch.Tensor) -> torch.Tensor:
    out = torch.empty_like(x)              # 1) 预分配输出（kernel 不会帮你分配）
    n_elements = out.numel()
    # 2) grid：需要多少个 program。写成 lambda，Triton 会把 constexpr 元参数传进来
    grid = lambda meta: (triton.cdiv(n_elements, meta["BLOCK_SIZE"]),)
    # 3) launch：kernel[grid](位置参数..., constexpr 用关键字传)
    add_kernel[grid](x, y, out, n_elements, BLOCK_SIZE=1024)
    return out


if __name__ == "__main__":
    torch.manual_seed(0)
    n = 98432                              # 故意不是 1024 的倍数，验证 boundary_check
    x = torch.rand(n)
    y = torch.rand(n)

    out_triton = add(x, y)
    out_torch = x + y

    torch.testing.assert_close(out_triton, out_torch)
    print(f"PASS: n={n}, 最大误差 = {(out_triton - out_torch).abs().max().item()}")
```

### 执行流程

1. 准备数据：创建两个长度为 98432 的 FP32 向量
2. 划分计算任务：每个 triton program 负责处理 1024 个元素，共启动 97 个 program
3. 加载数据：使用`tl.load()`从内存读取两个向量对应位置的元素
4. 执行加法：在计算单元中完成主逐元素加法
5. 写回结果：使用`tl.store()`将计算结果写入输出向量
6. 验证正确性：与 Pytorch 的 x\+y 计算结果比较

### Grid

计算网络

- 定义：由多个 program 组成的计算任务集合
- 作用：决定启动多少个 program 来完成整个计算任务
- 示例：`grid = (97,)`表示启动 97 个 program

### Program

程序实例

- 定义：triton kernal 的一个执行实例
- 作用：每个 program 负责处理数据中的一部分，不同 program 可以并行执行
- 示例：program 0 处理前 1024 个元素，program 1 处理接下来的 1024 个元素

### Block

数据块

- 定义：单个 program 一次处理的一组数据元素
- 作用：决定每个 program 的数据处理范围
- 示例：`BLOCK_SIZE = 1024`表示每个 program 处理 1024 个元素

### 小训练

alpha\_vec\_add：在 vec\_add 基础上，增加一个标量参数`alpha`

数学表达式：$out[i]=\alpha \times x[i]+y[i]$

程序：

```Python

import torch
import triton
import triton.language as tl
from triton.backends.spine_triton.driver import CPUDriver

triton.runtime.driver.set_active(CPUDriver())

@triton.jit
def alpha_add_kernel(X, Y, OUT, N, alpha, BLOCK_SIZE: tl.constexpr):
    pid = tl.program_id(0)
    offsets = pid * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
    mask = offsets < N

    x = tl.load(X + offsets, mask=mask, other=0)
    y = tl.load(Y + offsets, mask=mask, other=0)

    result = alpha * x + y
    tl.store(OUT + offsets, result, mask=mask)


def alpha_add(x, y, alpha=1.0):
    n = x.numel()
    out = torch.empty_like(x)
    BLOCK_SIZE = 1024
    grid = (triton.cdiv(n, BLOCK_SIZE),)

    compiled = alpha_add_kernel[grid](
        x, y, out, n, alpha, BLOCK_SIZE=BLOCK_SIZE
    )
    return out, getattr(compiled, "hash", None)


torch.manual_seed(0)
N = 98432
x = torch.rand(N, dtype=torch.float32)
y = torch.rand(N, dtype=torch.float32)

for a in [1.0, 2.0]:
    out, h = alpha_add(x, y, alpha=a)
    torch.testing.assert_close(out, a * x + y)
    print(f"alpha={a}: PASS; hash={h}")

out, h = alpha_add(x, y)
torch.testing.assert_close(out, x + y)
print(f"alpha=默认1.0: PASS; hash={h}")
```

和 vec\_add 的流程类似：

数据准备、任务划分、并行计算、正确性验证

## 仓库推荐的正确性测试

### test\_vec\_add

向量加法

- 实现逐元素计算 `output = x + y`，每个 Triton 程序处理 1024 个元素，通过掩码避免越界
- 包含与 PyTorch 结果比较、打印最大误差的函数。直接运行脚本会测试不同向量长度下 PyTorch 和 Triton 的性能。

### test\_softmax

按行 Softmax

- 每个 Triton 程序处理矩阵的一行，完成“减去最大值 → 指数 → 求和 → 归一化”，提高数值稳定性。
- 包含与 `torch.softmax` 对比的正确性断言，以及不同矩阵大小下的性能测试。

### test\_layernorm

LayerNorm 前向计算

- 按行计算均值、方差，再执行归一化和缩放偏移：`y = (x − mean) / sqrt(var + eps) * weight + bias`。
- 使用 FP32 计算统计量，并通过 `torch.autograd.Function` 封装，但没有实现反向传播。
- 当前正确性对比已被注释；性能测试函数只创建输入，尚未实际调用 LayerNorm。

### mm\_block\_ptr

使用块指针的矩阵乘法

- 实现 `C = A @ B`，重点演示 `tl.make_block_ptr`、带边界检查的加载与存储，以及 `tl.dot`。
- 每个程序计算一个 `32 × 32` 输出块，K 维一次加载，没有沿 K 分段累加的循环。
- 直接运行会计算 FP16 的 `256 × 256` 矩阵乘法，并与 PyTorch 校验结果。

### test\_smt\_mm

使用 SMT 扩展的矩阵乘法。

SMT 扩展是本项目为 triton 增加的一组接口，主要用于控制矩阵计算中的数据分块、内存布局、缓存和并行执行。

- 使用 `smt.descriptor_load`、`smt.view`、`smt.dot` 等接口，演示子块划分、数据复用及矩阵乘法。
- 提供沿 M 拆分、沿 M/N 拆分和沿 K 拆分三种路径；当前默认沿 K 每 256 个元素分段计算并累加，输出块为 `128 × 128`。
- 默认校验 FP16 的 `512 × 512` 矩阵乘法；设置 `RUN_PERF=1` 可额外输出平均耗时和 GOPS。
