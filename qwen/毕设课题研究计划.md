# 毕设课题研究计划

目前已经完成模型部署和性能基线，后续重点是源码、性能分析和优化实验。

1. 学习 Qwen 的计算过程

理解 Transformer 推理中的 Attention、RoPE、RMSNorm、FFN 和 KV Cache，并区分两个阶段：

* Prefill：并行处理输入，重点分析矩阵计算。
* Decode：逐 token 生成，重点分析权重读取、缓存访问和计算效率。

交付物：一张 Qwen 单层计算流程图，标明主要算子及张量形状。

2. 学习 K3 硬件和 llama.cpp 实现

重点学习 C/C++ 性能分析、RISC-V RVV、IME2、缓存/TCM、数据布局和多线程执行；沿着“Qwen 模型计算图 → GGML 算子 → SpacemiT 内核”追踪实际调用路径。

先从源码构建一个可复现版本，与当前预装版对照，并核实工作线程的核心调度。版本差异需要单独记录，避免误归因于优化。

交付物：源码构建环境、调用路径说明和可复现基线。

3. 通过 profiling 确定优化对象

分别测量 prefill 和 decode，记录热点算子的耗时占比、输入形状、精度及线程配置。初步候选包括量化矩阵乘、RMSNorm、Attention 相关计算，最终根据实测选择 1 个主攻算子，最多增加 1 个关联算子。

交付物：热点分析报告，说明“为什么选择这个算子、预计能改善多少整体耗时”。

4. 设计并实现优化

围绕确定的瓶颈提出可验证的假设，例如：

- 调整分块和权重布局，提高访存效率。
- 改善 RVV/IME2 的计算组织，提高硬件利用率。
- 减少中间数据搬运或重复计算。
- 调整线程分工，降低同步开销。
  每次只改变一个主要因素，并说明适用的张量形状、额外内存成本和可能的退化场景。

交付物：优化代码、单算子测试与逐项对比实验。

5. 验证正确性和端到端收益

先比较算子输出误差，再验证模型输出质量；量化计算允许的误差需要提前定义。性能评估同时覆盖：

* 单算子耗时与加速比。
* 模型 prefill/decode 吞吐和首 token 延迟。

* 内存占用，以及不同输入长度下的稳定性。

Qwen3-0.6B 用于快速迭代，随后可增加一个内存允许的较大 Qwen 模型，检查优化能否推广。单算子变快是否转化为模型变快，应作为核心结论。
